# Аудит текстов админки (для нетехнического пользователя)

Проект: `API-rope-shop` · админка `http://localhost/admin/` · дата: 05.11.2026

Проверено 7 экранов: **товары (список + редактор), заявки, настройки, тексты страниц (контент), отзывы, цвета, конфигуратор**.
Дополнительно просмотрены соседние экраны того же меню (контакты, галереи, разделы каталога) — только чтобы не потерять контекст.

Коротко: **сократить можно примерно треть живого текста (≈30–35 %), а ещё ≈2 300 слов статической вёрстки вообще не показываются пользователю** — их правят в файле, но на экране они не появляются. Именно в мёртвой вёрстке лежат самые человечные формулировки, а в живых экранах — самый технический язык.

---

## 1. Как считали и что не проверено

- Источник: исходники админки — `frontend/admin.html` и JS версии v2 (`frontend/js/views/admin`, `controllers`, `models`). Сборка по умолчанию `CATALOG_V2 = true` (`frontend/js/api/config.js:8`), поэтому работают «новые» экраны.
- Считались слова, которые видит пользователь: заголовки, подписи полей, легенды, подсказки, тексты кнопок, пустые состояния, ошибки/тосты/подтверждения.
- **Не** считались: данные из БД, `aria-label` (озвучка для скринридеров), значения-примеры внутри полей, тексты в комментариях кода.
- Цифры приблизительные (ручной подсчёт по строкам, погрешность ±10 %). Для статического HTML дополнительно был механический подсчёт слов по секциям.
- **Ограничение:** живой интерфейс не прокликивался (нет браузерного инструмента в этой сессии). Вывод «видно/не видно» сделан по ветвям кода — где какой `innerHTML` перезаписывает панель. Это надёжно для структуры, но визуальную плотность экрана я не проверял глазами.
- Термины «видно сразу» и «с раскрытыми формами» — оценка: часть форм спрятана в сворачиваемых блоках `<details>` и раскрывается по клику.

## 2. Главное открытие: ~2 300 слов мёртвого текста

Часть `frontend/admin.html` при загрузке **перезаписывается JavaScript** и пользователю не показывается никогда.

| Блок в `admin.html` | Строки | Слов | Что происходит на самом деле |
|---|---|---|---|
| `#panel-home` («Главная страница», редактор блоков) | 123–471 | **≈583** | Панель недостижима из меню; `AdminView.showUnavailablePanels()` (`frontend/js/views/admin/AdminView.js:67–76`) заменяет её сообщением «Редактирование этого раздела пока недоступно…». |
| `#panel-reviews` (макет отзывов) | 472–609 | **≈216** | Полностью затирается: `AdminContentView` в конструкторе делает `root.innerHTML=…` (`frontend/js/views/admin/AdminContentView.js:10`), а живой экран рисует `AdminReviewsView`. |
| `#panel-contacts` (макет контактов) | 613–672 | **≈88** | Тоже затирается (`AdminContactsController` → `ContactsView` → `AdminContentView.js:10`). Живой экран контактов — 3 поля + «Входящие обращения». |
| `#panel-configurator` («красивый» конфигуратор с формулами) | 675–1382 | **≈1 340** | Стирается `AdminConfigView.js:55–56` (`root.removeAttribute('data-savable'); root.innerHTML=…`). Живой экран — абстрактный справочник из 7 разделов. |
| `#panel-business`, `#panel-private`, `#panel-charity` | 1396–1433 | **≈70** | Заменяются тем же `showUnavailablePanels()`, пунктов меню для них нет. |
| `#panel-settings` | 612 | 0 | Пустая секция, всё рисует `AdminSettingsController.js:35`. |
| `frontend/js/admin.js` | 52 строки | — | Legacy-инициализация сайдбара/фильтров; ни один HTML её не подключает (в `admin.html` грузится `/js/app.js`, контроллер админки регистрируется в `app.js:23`). |

**Итого ≈2 300 слов мёртвого текста — это больше, чем весь живой интерфейс админки.**

Почему это важно для правок:

1. Любая правка «по старому месту» (например, в `admin.html:123–471`) не изменит ничего на экране. Копирайтер будет править текст, которого никто не видит, и удивляться.
2. Парадокс качества: мёртвые тексты написаны заметно человечнее живых.

| Мёртвый, но хороший текст | Живой аналог |
|---|---|
| «Верёвка без фона… Та же верёвка, что на фото, но вырезанная» (`admin.html:193`) | — такого объяснения в живом UI нет |
| «Три цифры в правом нижнем углу… Слева — сама цифра, справа — короткая подпись» (`admin.html:234–236`) | — |
| «Чтобы начать новый абзац, нажмите Enter два раза — оставьте пустую строку» (`admin.html:274`) | — |
| «Цены, тросы, цвета и варианты концов меняются в отдельном разделе» (`admin.html:386`) | «Заполняйте разделы по порядку: сначала справочники, затем тарифы…» (`AdminConfigView.js:57`) |
| Кнопка «Открыть цены» из редактора главной (`admin.html:387`) | живой конфигуратор потерял кнопку «Посмотреть на сайте» |

**Рекомендация:** не «удалить и забыть», а перенести 5–7 лучших формулировок в живые экраны (они перечислены в §7), остальное удалить вместе с мёртвыми секциями, чтобы файл перестал вводить в заблуждение.

## 7. Оценка: сколько текста можно убрать и где его не хватает

### 7.1 Сколько можно убрать

| Экран | Убрать без потери смысла |
|---|---:|
| Товары — список | ≈25 % |
| Товары — редактор | ≈40 % |
| Заявки | ≈30 % |
| Настройки | ≈45 % (в основном два вводных абзаца) |
| Тексты страниц | ≈25 % |
| Отзывы | ≈35 % |
| Цвета | ≈40 % |
| Конфигуратор | ≈25–30 % (в основном дубли подсказок) |
| **Итого по живому UI** | **≈30–35 % (~800–900 слов из ~2 600)** |
| Мёртвый HTML | **100 % (~2 300 слов)** |

### 7.2 Где наоборот не хватает ОДНОЙ понятной подсказки

1. **Что такое «заделка»** — до первого упоминания (`AdminProductsView.js:476`). Сейчас слово встречается 6 раз без объяснения.
2. **Что такое «сращивание»** (`AdminProductsView.js:452`) — «соединение двух тросов в один».
3. **Где блок появится на сайте** — в «Текстах страниц» этого нет. Одна строка: «Каждый блок — это заголовок и текст на сайте; фото общие для трёх языков».
4. **Отзывы: «Одобрен» vs «Опубликовать после одобрения»** (`AdminReviewsView.js:55`, `:58`) — выглядит как двойное подтверждение. Нужна одна строка-связка.
5. **Тарифы: сохраняются отдельной кнопкой** (`AdminTariffTable.js:39`, `AdminConfigController.js:52`) — сейчас узнаётся только из ошибки.
6. **Настройки: кто получает уведомление** — у трёх галочек (`AdminSettingsController.js:15–17`) нет получателя; и где взять номер чата Telegram.
7. **«Активен» = «показывать на сайте»** (`AdminColorsView.js:54`, `AdminConfigModel.js:2`).
8. **«Код» заполняется автоматически** (`AdminConfigModel.js:34–48`) — сейчас об этом ни слова, а поле обязательное.
9. **Нижняя кнопка «Сохранить изменения» сохраняет всё сразу** — в подписи `savebar` (`frontend/admin.html:1437–1441`) есть «Изменения появятся на сайте только после нажатия этой кнопки», но не сказано, что это касается всех блоков.
10. **«Порядок» = место в списке на сайте** — влияет на каталог, цвета, отзывы, справочники; формулировка «(меньше — выше)» есть не везде.

### 7.3 Приёмы, которые дадут эффект без переписывания всего

- Оставить у поля **либо** подпись, **либо** подсказку — сейчас они часто дублируют друг друга (`AdminProductsView.js:459/461`, `464/466`; `AdminConfigModel.js:15–16` против `AdminConfigView.js:47`).
- Технические «не удалось подтвердить…», «часть изменений могла сохраниться» заменить на два действия: «что случилось» + «что нажать».
- В тосты не подставлять `error.message` от сервера (`AdminProductsController.js:82`, `:190`, `:207`, `:222` и др.) — пользователь может увидеть английский текст.
- Вернуть в живые экраны 3 удачных блока из мёртвой вёрстки: «Что делать с новым отзывом» (`admin.html:481–488`), пошаговую инструкцию из 3 шагов (`admin.html:137–150`), подсказку про пустую строку для нового абзаца (`admin.html:274`).

## 8. Итог
