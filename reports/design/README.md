# Скриншоты загрузки каталога (скелетоны)

Снято в headless Chrome (puppeteer-core, локальный Chrome) на `http://localhost` с искусственной
задержкой API 6 секунд (подмена `window.fetch` до загрузки страниц). Язык сайта публичных страниц
по умолчанию — немецкий (`getLanguage()` в `frontend/js/i18n/locale.js`), поэтому подписи на скриншотах немецкие.

## Замеры (скелетон → финальный контент)

| Страница | 1440 px | 390 px |
| --- | --- | --- |
| `/catalog/`, блок разделов | 683 → 683 px, CLS 0.0014 | 1327 → 885 px, CLS 0 |
| `/catalog/`, галерея работ | 802 → 802 px (сетка 705 → 705) | 1773 → 1488 px |
| `/category/?group=1` | 1679 → 1098 px, CLS 0.0014 | 1688 → 1850 px, CLS 0.2835 |

На `/catalog/` высоты скелетона и контента совпадают на 1440 px; CLS около нуля, потому что
скелетон разделов стоит в статичной разметке `catalog.html` и резервирует место с первого кадра.

На мобильном у `/catalog/` число карточек-заглушек (6) больше числа разделов в локальной БД (4),
поэтому блок «сжимается» на 442 px уже после загрузки (визуально это ниже первого экрана — CLS 0).
Галерея: 6 заглушек = размер страницы (`data-gallery-page-size="6"`), в БД 5 фото.

На `/category/` скелетоны создаются только из JS (разметку `category.html` по границам задачи
не меняли), поэтому до первого кадра страница резервирует лишь `min-height` из `catalog-filter.css`,
и после появления скелетона контент ниже сдвигается — это основной вклад в CLS 0.2835 на 390 px.

## Замечание по данным

В локальном `/api/work_photos` ссылки ведут на `/assets/work_photos/...`, но каталог `media/work_photos/`
пуст, поэтому на скриншотах `catalog-gallery-loaded-*` вместо фото — битые изображения.
Это состояние данных/медиа, а не скелетонов: скелетон в этот момент уже удалён из DOM.
