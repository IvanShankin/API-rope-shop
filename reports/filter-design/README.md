# Фильтр на странице категории: аудит и варианты редизайна

Дата: 2026-11-05 · ветка `dev` · страница: `http://localhost/category/?group=1`
Публичный язык по умолчанию — немецкий: в интерфейсе «Konstruktion», «Durchmesser, mm»,
«Im Konfigurator verfügbar», «Filter zurücksetzen». Сквозной пример — категория «Cruising Tauwerk»
(2 товара, диаметры 8–16 мм).

Это дизайн-исследование, не реализация. Файлы `frontend/` не менялись: макеты A/B/C живут только
в памяти страницы (подмена CSS + небольшой DOM-патч), логика фильтра не трогалась.

## 2. Сейчас → почему плохо

Все числа ниже — из `before-measurements.json` (computed styles + пиксели скриншотов) или
рассчитаны по WCAG-формуле для этих же цветов. «Норма» — WCAG 2.2: 1.4.3 — 4.5:1 для обычного
текста, 1.4.11 — 3:1 для границ/состояний элементов управления.

## 3. Что реально фильтрует, а что декоративно

Проверялось кликами по настоящему списку SlimSelect (не установкой `value` из скрипта):

| Контрол | Пишет в URL | Меняет список товаров | Факт |
|---|---|---|---|
| `Konstruktion` | Да, `construction=polyester_core` | **Нет** | В категории 2 товара, у обоих `construction_type = polyester_core` — единственная реальная опция. Выбор ничего не меняет. Механизм рабочий, проявится в категориях со смешанными конструкциями |
| `Durchmesser, mm` | Да, `diameter=16` | **Да** | 2 товара → 1 товар; сброс возвращает 2. Проверено на 1440 и 390 |
| `Im Konfigurator verfügbar` | Да, `configurator=1` | **Нет** | У обоих товаров `has_configurator = true` и есть активные варианты — фильтр не отсекает ничего. В этой категории декоративен |
| `Filter zurücksetzen` | Очищает параметры (`?group=1`) | **Да** | Сбрасывает значения и возвращает 2 товара; disabled, пока фильтров нет — это корректно |
| Счётчик результатов | — | — | Строка `filterLabels.count` («Найдено товаров:») в коде есть, но нигде не выводится |
| Заголовок «Фильтр» | — | — | Есть только в `aria-label`, визуально отсутствует |

Вывод: на этой странице **2 из 3 контролов визуально «мёртвые»**. Пользователь выбирает
«Konstruktion» или чекбокс, ничего не происходит — и это усиливает ощущение «фильтр не работает».
Отсюда рекомендация: в любом варианте показывать число найденных товаров и/или не показывать
контрол, который в текущей категории не меняет выдачу. Решение — за владельцем (см. §8).

## 5. Варианты

### A. «Тихая панель» — только CSS + 1 строка разметки

Идея: панель остаётся прозрачной и в той же колонке 230px, но перестаёт быть набором плит.
Появляется заголовок «Filter» (Inter Tight 24px), подписи становятся микротекстом 12px 600,
значения — 15px 500. Поля получают спокойную поверхность `#112846` с рамкой и радиусом 12px,
чекбокс — кастомный 20×20 с заливкой-снегом и тёмной галочкой, сброс — ghost-pill 999px.
Добавлены hover, focus-visible и аккуратный выпадающий список в палитре сайта.

Что меняется: **только CSS** (~120 строк) + **одна строка разметки** — в
`CatalogView.renderFilters` перед `fieldset` добавить
`<h2 class="catalog-filter__title">${label('title')}</h2>`. Логика фильтрации, URL, модель и
SlimSelect не трогаются. Класс заголовка в CSS уже существует — он просто не использовался.

Цена: 0.5–1 день с проверкой RU/EN/DE.

Риски: минимальные, потому что меняется только оформление. Остаётся слабая обводка полей
(2.02:1, норма 3:1) — доводится одним значением alpha (§7). Нет счётчика результатов и чипов.

Скриншоты: `variant-a-1440.png`, `variant-a-filter-1440.png`, `variant-a-applied-1440.png`,
`variant-a-reset-1440.png`, `variant-a-390.png`, `variant-a-applied-390.png`.

### B. «Карточка фильтра со счётчиком и чипами» — CSS + разметка + небольшой JS

Идея: та же типографика, что в A, но панель становится карточкой на поверхности `#0F2442`
(радиус 20px). Сверху — «Filter» и счётчик «2 Produkte», снизу — активные фильтры чипами
(«Durchmesser: 16 mm ×»), сброс — полноширинная ghost-кнопка. Карточка шире: 268px вместо 230px.

Что меняется: CSS из A + ~60 строк CSS; в разметку добавляются head (заголовок + счётчик) и
контейнер чипов; в `syncFilters` (туда уже передаётся `products.length`, но значение
игнорируется) выводятся счётчик и чипы; клики по «×» вызывают `onFilterChange` с текущими
значениями. Логика фильтрации не меняется, но JS во view становится больше.

Цена: 1.5–2 дня.

Риски: средние — появляется состояние чипов, которое надо синхронизировать с моделью и URL
(риск рассинхрона); на 390 фильтр выше (365px против 232px у A) — первый экран каталога уезжает
вниз; в макете чипы/счётчик обновляет вставленный helper, в реальной реализации это надо
подключить к `syncFilters` и проверить на back/forward.

Скриншоты: `variant-b-1440.png`, `variant-b-filter-1440.png`, `variant-b-applied-1440.png`,
`variant-b-reset-1440.png`, `variant-b-390.png`, `variant-b-applied-390.png`.

### C. «Filterleiste над каталогом» — CSS + разметка + JS (смена структуры)

Идея: фильтр уходит из левой колонки в горизонтальную полосу над товарами: слева «Filter»,
дальше два селекта, чекбокс; справа — счётчик и «Filter zurücksetzen». Полоса липкая, с
полупрозрачным фоном. Товары занимают всю ширину под ней. На мобильном предполагается
свёрнутая кнопка «Filter» и панель-шторка.

Что меняется: CSS-раскладка (одна колонка, sticky-полоса, горизонтальная сетка полей),
разметка (head с заголовком и счётчиком) и **JS**: мобильный drawer (открытие/закрытие,
focus-trap, Escape), счётчик, согласование sticky-отступов. В макете мобильный drawer не
реализован — на `variant-c-390.png` показана только CSS-раскладка.

Цена: 3–5 дней + QA.

Риски: высокие. Меняется структура страницы (это против договорённости «сначала проход по
токенам, без смены структуры»). Липкая полоса конфликтует с уже липкой галереей товара
(`.product__gallery { position: sticky; top: header + 24px }` — тот же отступ): картинка будет
уезжать под полосу, нужен новый offset для всех sticky-блоков. Плюс CLS/скролл, отдельная
a11y-работа для шторки, проверка 768/1024.

Скриншоты: `variant-c-1440.png`, `variant-c-filter-1440.png`, `variant-c-applied-1440.png`,
`variant-c-reset-1440.png`, `variant-c-390.png`, `variant-c-applied-390.png`.

## 7. Рекомендация

**Внедрять A.** Это единственный вариант, который закрывает почти все претензии владельца
(нет заголовка, подписи и значения одного веса, тёмный чекбокс, «disabled-ссылка» вместо
кнопки, чужие радиусы и синие состояния) и при этом не трогает логику фильтрации, URL и
SlimSelect. По трудозатратам — 0.5–1 день, риск минимальный. A уже снимает «плиту»: поля
получают свою поверхность и границу, состояния — палитру сайта.

**B — следующий шаг**, если владельцу важно видеть «сколько нашлось» и активные фильтры:
счётчик и чипы частично решают проблему декоративных контролов (пользователь видит, что
фильтр применён и что он дал). Но это уже правки JS и новый код синхронизации — не в один заход
с токенами.

**C — не рекомендую в этой итерации.** Смена структуры, JS для мобильного drawer, конфликт
со sticky-галереей товара и риск CLS. Идея рабочая, но её стоит рассматривать после того, как
токены и панель будут приведены в порядок.

### Доводка до внедрения (одно значение CSS)

В макетах обводка полей — `rgba(179,207,229,.22)`: это **2.02:1** к фону страницы, ниже нормы
3:1 для границ контролов. Перед реализацией поднять до `rgba(179,207,229,.38)` — ровно **3.0:1**
(проверено расчётом по этим же цветам). Обводка кнопки сброса — `rgba(179,207,229,.28)` = **2.0:1**;
поднять до `.46` = **3.3:1**. На скриншотах эти два значения ещё «старые» — переснимать их ради
этого не требуется, композиция не меняется. Чекбокс уже проходит: рамка `.5` = **3.64:1**,
заливка-снег = 16.73:1, галочка `#0A1931` на снеге = 16.73:1.

## 8. Что осталось нерешённым (нужно решение владельца)

1. **Какой вариант: A, B или C.** Рекомендация — A сейчас, B как следующий шаг.
2. **Что делать с декоративными контролами.** Варианты:
   - оставить оба, но добавить счётчик «N Produkte» (в B он есть, в A его нет) — минимально;
   - скрывать контрол, если он не меняет выдачу в текущей категории (нужен JS);
   - показывать disabled-состояние с пояснением (например, «в этом разделе одна конструкция»).
   Оставить как есть — тоже вариант, но тогда ощущение «не работает» останется.
3. **Счётчик результатов в A.** В коде уже есть `filterLabels.count` и в `syncFilters` уже
   приходит количество, но игнорируется; вывод счётчика — 2 строки разметки + 1 строка в
   `syncFilters` (это уже небольшая правка JS, не только CSS).
4. **Радиус полей:** 12px (как в макете) или 14px (как у полей сайта). В макете 12 — компромисс,
   чтобы не спорить с 10–14; в реализации лучше 14, если важна консистентность с формами сайта.
5. **Заголовок и локаль:** заголовок делать через `label('title')` — RU «Фильтр», EN/DE «Filter».
   В макете стоит немецкий вариант, потому что страница по умолчанию немецкая.
6. **Не проверено:** hover/focus-скриншоты вариантов; RU/EN; клавиатурный обход; ширины
   768/1024; другие категории (там конструкций может быть несколько — фильтр поведёт себя иначе);
   поведение back/forward с чипами в B.
