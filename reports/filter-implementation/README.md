## 3. Контрасты (WCAG 2.2, расчёт)

Метод: альфа-цвета компонуются с фоном, на котором они реально рисуются
(`background-clip: border-box` — фон поля виден и под рамкой, поэтому рамка поля
компонуется с заливкой `#112846`, остальные — с фоном страницы `#0A1931`), затем
контраст по формуле WCAG. Значения цветов брались из computed styles живого сайта,
скрипт: `scripts/lib.mjs` (`blend`, `contrast`).

| Что | До (живой сайт) | После | Порог |
|---|---|---|---|
| Обводка поля к фону страницы | `#36577A` на `#0A1931` = **2.34:1** | `#4F6782` на `#0A1931` = **3.00:1** | 3:1 ✓ |
| Обводка кнопки сброса к фону | обводки не было (текст-ссылка) | `#586D84` на `#0A1931` = **3.29:1** | 3:1 ✓ |
| Обводка чекбокса к фону | рамка нативного `#858585` = 4.76:1, но заливка `#3B3B3B` = **1.57:1** | `#5F748B` на `#0A1931` = **3.64:1** | 3:1 ✓ |
| Включённый чекбокс | белая плашка, галочки нет | снег `#F6FAFD` на фоне = **16.73:1**, галочка `#0A1931` на снеге = **16.73:1** | — |
| Микро-подпись поля (12px) | 14px, 16.73:1 | `#8098AF` на `#0A1931` = **5.87:1** | 4.5:1 ✓ |
| Значение в поле | 10.58:1 | `#F6FAFD` на `#112846` = **14.13:1** | 4.5:1 ✓ |
| Текст кнопки сброса | 16.73:1 (активна), 3.65:1 (disabled) | **16.73:1** (активна), disabled-состояние исключено из 1.4.11 | 4.5:1 ✓ |
| Hover-рамка поля | — | `#6C87A2` на hover-заливке `#152E4F` = **3.66:1** | 3:1 ✓ |

Замечание: обводка поля `.38` даёт ровно **3.00:1** именно к фону страницы; к собственной
заливке поля (внутренняя сторона рамки) — 2.54:1. Критерий README §7 сформулирован
«к фону страницы» — он выполнен. Для сравнения: на макетах было `.22` = 2.02:1, в живом
CSS до правок — `.18` = 2.34:1.

### 4.2 CLS (layout shift)

Медиана 2 прогонов на состояние (`cls-comparison.json`); методика: тот же живой сайт,
«до» подменяет CSS/JS на версии из `HEAD` через перехват запросов, «после» — текущие файлы.

| | До | После | Вывод |
|---|---|---|---|
| 1440 | ≈0.001 | ≈0.001 | без изменений, шум |
| 390 | **0.1932** | **0.2107** | +0.0175 |

Сдвиг — один и тот же существовавший до правок: панель фильтра появляется в один кадр с
товарами и сдвигает их вниз (time сдвига совпадает с моментом `hidden=false`; блокировка
веб-шрифтов результат не меняет). Нового источника сдвига нет; на мобильном он стал чуть
больше, потому что панель по утверждённому макету выше на 23px. Оба значения остаются в
зоне «needs improvement» (0.1–0.25), в «poor» (>0.25) не уходим. Чтобы убрать и этот
остаток, нужно резервировать высоту фильтра до загрузки данных — это JS-правка вне
варианта A (см. §7).

## 7. Что не проверено / известные ограничения

1. **Поиск внутри списка на широких категориях.** На `?group=2` в диаметрах 11 значений,
   SlimSelect показывает строку поиска. Она остаётся старой (заливка `#1A3D63`, плейсхолдер
   на русском «Найти…» при немецкой странице) — вариант A в §10 её не описывает, поэтому
   не стилизовал. Поведение рабочее, видно на `after-group2-select-open-1440.png`.
   Рекомендация: отдельным шагом прогнать строку поиска по токенам варианта A
   (фон панели/рамка `--color-line`) и вынести плейсхолдеры в локализацию.
2. **Мобильный CLS +0.0175** (0.1932 → 0.2107) — см. §4.2: тот же существовавший сдвиг,
   выросший из-за +23px высоты панели. Полное устранение требует резервирования высоты
   фильтра до загрузки данных (JS/скелетон), это вне рамок CSS-варианта A.
3. Контрасты посчитаны по computed styles и WCAG-формуле с учётом композиции альфы,
   а не пиксельным сэмплированием новых скриншотов (для «до» модель композиции
   подтверждена пикселями из `reports/filter-design/before-measurements.json`:
   рамка `.18` над `#1A3D63` = `#36577A`).
4. Не проверялись: back/forward с применённым фильтром, Firefox/Safari, ширина 320px,
   `prefers-reduced-motion`, полный клавиатурный обход страницы за пределами фильтра.
5. SlimSelect/`custom-selects.*` не менялись; логика фильтрации, модель и URL не менялись.
